第一章 · 软件总览

软件总览

「禁止使用转盘（TryMultiUse）」是一个方舟生存进化服务端 ArkApi 插件，当前版本 1.0。它在服务器引擎层接管「多选项交互」入口，玩家再对幸运转盘类物品点下选项时，服务器直接不予响应——转盘玩法即刻全服禁用，无需改模组、无需换地图。

🎡

转盘交互拦截

在引擎层接管多选项交互，转盘选项一点即拦，全服立即生效。

🎯

多规则自由配置

拦截规则写在 config.json 里，想加几条加几条，按索引或蓝图精确匹配。

🛡️

其余交互零影响

不命中规则的交互原样放行，正常玩法不受干扰。

⚙️

JSON 配置文件

插件目录下 config.json 集中管理配置，启动时自动读取。

🔄

配置热重载命令

控制台 / RCON 执行 TryMultiUse.Reload，免重启刷新配置。

📝

中文日志自适应编码

控制台中文输出自动适配 ArkApi 3.54 / 3.55 编码，不乱码。

拦截规则完全由 config.json 的 BlockRules 数组配置（依据源码 Main.cpp 的 Hook_AActor_TryMultiUse：按配置的规则表顺序匹配，第一条命中即拦截并弹该条自己的气泡提示）。规则怎么加、提示怎么配见第四章 BlockRules 小节；未配置或列表为空时不拦截任何交互。
第二章 · 环境要求

环境要求

项目要求
操作系统Windows（服务端为 Windows 版方舟生存进化服务器）
服务端插件框架ArkApi，最低版本 3.5（依据 Output/PluginInfo.json 的 MinApiVersion 字段）
运行依赖无额外运行库、无数据库、无网络服务依赖（依据源码：插件仅挂钩引擎交互函数，无任何数据库调用，配置文件中也没有数据库小节）

第三章 · 部署安装

部署安装

以下为拿到编译好的插件后在服务器上的部署步骤。

  1. 确认服务器已安装 ArkApi

    检查服务器目录 ShooterGame\Binaries\Win64\ArkApi\ 是否存在 → 存在则继续；不存在请先安装 ArkApi（最低 3.5）。

  2. 复制插件文件

    把 PluginInfo.json、config.json、TryMultiUse.dll 复制到 ShooterGame\Binaries\Win64\ArkApi\Plugins\TryMultiUse\ → 目录不存在时先创建（工程自带的 一键安装.bat 会自动完成复制与建目录，并可选择同时部署停用副本 TryMultiUse.dll.arkapi）。

  3. 检查配置文件

    打开插件目录下的 config.json，确认内容为合法 JSON → 配置详解见第四章。

  4. 重启服务器

    启动方舟服务器 → 服务器控制台出现「先锋.禁止使用转盘(1.0) 先锋方舟服主群:138535385 作者QQ:711919」横幅日志即表示插件加载成功（源码 Main.cpp 的 Load()）；随后输出「已加载 N 条拦截规则」（出厂预置为 2 条），这是拦截规则加载正常的标志；测试版还会输出一行「调试输出,测试编码」自检，这行中文显示正常就说明控制台编码匹配。

  5. 验证插件已生效

    进服对转盘物品使用转盘选项 → 选项无反应即拦截生效；其余交互（开门、开箱等）正常放行。

  6. 验证重载命令

    在服务器控制台或 RCON 执行 TryMultiUse.Reload → 返回 Reloaded config 表示命令可用。

若 config.json 缺失或不是合法 JSON，插件加载时会抛出错误 Can't open config.json（源码 Main.cpp 的 ReadConfig()），插件将无法正常启动。部署前务必确认配置文件存在且格式正确。
编译产物位于工程 Output\TryMultiUse\ 目录；首次使用编译脚本前需先运行 环境变量.bat 设置 ASE_API（用户级永久环境变量，重启命令行 / VS 后生效）。

第四章 · 配置详解

ConsoleEncoding 控制台编码

什么意思：控制插件往服务器控制台输出文字时用的编码。不同版本 ArkApi 的服务器控制台编码不同（3.54 为 GBK/ANSI，3.55 为 UTF-8），编码不匹配时控制台中文会乱码。本插件输出前会按这个配置决定是否把 UTF-8 转成 GBK（Main.cpp 的 应用控制台编码配置，插件日志模块 h/日志.h 的自动输出系列同受其控制）。

兜底值：auto（配置缺失或值非法时都按 auto 处理，非法值会在控制台提示一行黄色警告）

{
  "ConsoleEncoding": "auto"
}

怎么修改：可选值共三个（大小写不限）：

取值效果
auto自动探测：控制台代码页为 936 时转 GBK 输出，否则按 UTF-8 原样输出。3.54 / 3.55 服务器都不用改配置，推荐保持默认
gbk强制输出前转 GBK（等同旧版行为；写 ansi 也可以）
utf8强制 UTF-8 原样输出（写 utf-8 也可以）
改完不用重启：控制台 / RCON 执行 TryMultiUse.Reload 即可热生效（编码解析在每次读取配置时进行）。
第四章 · 配置详解

BlockRules 拦截规则与气泡提示

什么意思：拦截规则全部写在 BlockRules 数组里，想禁几个交互就写几条规则；每条规则带自己的气泡提示——文案、颜色、大小、时长各是各的。命中任一规则即拦截该次交互并弹该规则的提示，不再让玩家误以为卡 bug（源码 Main.cpp 的 Hook_AActor_TryMultiUse + 应用拦截规则配置，提示经 ArkApi 的 SendNotification 发送）。

规则怎么匹配：

  • 规则内是"与"：UseIndex 和 Blueprint 都写 = 两者同时满足才拦；只写一个 = 单条件匹配。
  • 规则间是"或"：任何一条命中就拦截；多条同时命中按数组顺序取第一条，弹它的提示。
  • Blueprint 为完整蓝图路径精确匹配——测试版插件每次交互会在控制台输出「蓝图:」行，直接复制过来用即可。
  • 两条条件都不写的规则无效，加载时跳过并黄色警告；BlockRules 未配置 / 不是数组 / 为空 = 不拦截任何交互（控制台有黄色提示）。

出厂预置（即默认的"禁止使用转盘"两条规则，可直接在其上加改）：

{
  "BlockRules": [
    {
      "UseIndex": 52126,
      "Tip": { "Enabled": true, "Message": "转盘已被服务器禁用", "Color": "red", "Scale": 1.0, "Time": 3.0 }
    },
    {
      "Blueprint": "Blueprint'/Game/Mods/TXWS/Item/LXXXXXXX.LXXXXXXX'",
      "Tip": { "Enabled": true, "Message": "转盘已被服务器禁用", "Color": "red", "Scale": 1.0, "Time": 3.0 }
    }
  ]
}

如何新增拦截规则（照着做就行）：

  1. 拿到要拦的值

    部署测试版插件 → 进服对要禁的交互操作一次 → 控制台输出「TryMultiUse:数字」（填 UseIndex）和「蓝图:路径」（填 Blueprint）两行，复制你要用的那个值。

  2. 在数组末尾加一条规则

    打开 config.json，在 BlockRules 数组最后一条 } 后面加一个逗号，另起一行粘贴新规则——用哪种条件就写哪个键，另一个不用写。

  3. 按需配提示

    想自定义提示就写 Tip 小节（文案 / 颜色 / 大小 / 时长见下方字段表）；整个 Tip 不写就用默认提示；想拦但不提示就写 "Enabled": false。

  4. 热重载生效

    控制台 / RCON 执行 TryMultiUse.Reload → 看到「已加载 N 条拦截规则」且数量比之前多一条，即加载成功。

  5. 进服验证

    对目标交互再操作一次 → 被拦（配了提示的弹出对应提示）即成功；没拦到就对照调试输出的值检查拼写是否一致。

多条规则示例（3 个蓝图 + 2 个索引混着加，照抄后把值换成自己的即可）：

{
  "BlockRules": [
    { "UseIndex": 52126, "Tip": { "Message": "转盘已被服务器禁用" } },
    { "UseIndex": 52127, "Tip": { "Message": "抽奖已关闭", "Color": "yellow" } },
    { "Blueprint": "Blueprint'/Game/Mods/TXWS/Item/LXXXXXXX.LXXXXXXX'" },
    { "Blueprint": "Blueprint'/Game/Mods/其他模组/物品A.物品A'", "Tip": { "Message": "该物品已停用", "Scale": 1.5, "Time": 5.0 } },
    { "Blueprint": "Blueprint'/Game/Mods/其他模组/物品B.物品B'", "Tip": { "Enabled": false } }
  ]
}
规则数量没有上限：同种条件重复加、索引与蓝图混着加都行，每条规则独立匹配、各弹各的提示（多条同时命中按数组顺序取第一条）。要拦同一个物品的多个选项，就多写几条索引规则。

Tip 字段（每条规则各自的提示，可省略任意项）：

第六章 · 常见问题

常见问题

控制台中文乱码（方块/问号）？
先试这个：看插件启动时自检输出的「调试输出,测试编码」行——这行中文显示正常就说明编码匹配，无需处理；若这行乱码，保持 ConsoleEncoding 为 auto（插件会按服务器控制台代码页自动选择编码）并执行 TryMultiUse.Reload；仍乱码再按 ArkApi 版本显式指定——3.54 服务器设 gbk、3.55 服务器设 utf8。
插件没加载，控制台提示 Can't open config.json？
先试这个：检查 ArkApi\Plugins\TryMultiUse\config.json 是否存在、文件名拼写是否正确；存在则用 JSON 校验工具检查格式（多逗号、缺引号都会导致解析失败）。
改了 config.json 但没生效？
先试这个：在控制台或 RCON 执行 TryMultiUse.Reload 热重载；若提示 Failed to reload config 说明新配置格式有错，按报错修正后重试。仍不生效则重启服务器。
转盘还能用，没被拦截？
先试这个：确认插件已加载（控制台有「先锋.禁止使用转盘(1.0)」横幅），再看启动 / 重载时输出的「已加载 N 条拦截规则」是否大于 0。拦截范围由 BlockRules 配置决定——你服上的转盘若来自其他模组/其他物品，用测试版插件对它交互一次，把控制台「TryMultiUse:」行里的数字填进 UseIndex（或「蓝图:」行的路径填进 Blueprint）加一条规则，执行 TryMultiUse.Reload 即可，详见第四章。
会不会误伤其他交互（开门、开箱、修理等）？
不会。插件只在上面的两条拦截规则命中时拦截，其余交互原样交给游戏原函数处理（源码 Hook_AActor_TryMultiUse：未命中即调用原函数）。部署后建议抽查几项常用交互确认。
怎么临时停用插件？
把插件目录下的 TryMultiUse.dll 改名为 TryMultiUse.dll.arkapi（ArkApi 不加载该后缀），重启服务器即可停用；改回 .dll 恢复。工程的 一键安装.bat 也支持部署停用副本。
怎么关掉 / 修改拦截时给玩家的提示？
先试这个：提示是每条规则各自的——改 config.json 里对应规则内的 Tip 小节：Enabled 改 false 静默拦截，Message 改文案，Color / Scale / Time 调颜色、大小、时长；然后执行 TryMultiUse.Reload 热生效，详见第四章 BlockRules 小节。
配置文件放哪里？改坏了怎么恢复？
配置固定在 ShooterGame\Binaries\Win64\ArkApi\Plugins\TryMultiUse\config.json，与 TryMultiUse.dll 同目录。改坏了先用备份覆盖回去；没有备份时，参照本教程第四章的示例片段重建，保证 JSON 语法完整（逗号、引号齐全）。
测试版控制台一直刷 TryMultiUse:数字 / 蓝图:路径？
这是测试版的调试输出：每次玩家触发多选项交互都会打印选项索引与物品蓝图（源码 Hook_AActor_TryMultiUse 的调试分支），用于排查拦截规则——把「TryMultiUse:」的数字填进 UseIndex、「蓝图:」的路径填进 Blueprint 就是现成的规则条件。正式版自动关闭这类输出，不影响功能。
旧版配置（BlockTip / 写死的规则）怎么升级？
旧版 BlockTip 小节已被 BlockRules 数组取代（旧字段会被忽略）。用本教程第四章的出厂预置直接覆盖 BlockRules 即可，原有的两条禁转盘规则已在预置里；自己加过的提示样式照着搬进对应规则的 Tip 小节。
